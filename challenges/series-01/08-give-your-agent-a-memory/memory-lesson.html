Lesson 8 · give your agent a memory

Your colleague has amnesia — by design

Every new task starts blank. Today you write the file that fixes that — once, in your own words.

Amnesia, by design

Nothing from yesterday's conversation survives into a new task unless it was written into a file. That's not a defect to fight with longer chats — it's a fact you engineer around. The fix is a file named CLAUDE.md: the agent reads it at the start of every session in that folder, so whatever it says, your colleague knows from minute one. It's the difference between a temp on their first day and someone who's worked with you for a year.

Four short sections, in your words:

  • Who I am — name, role, what I work on (two lines)
  • How I like output — tone, formats, length defaults
  • Always — e.g. "flag anything you're not certain of"
  • Never — e.g. "never delete files without asking me"

Where it lives — and where it works

The file belongs in the folder where your real work happens — it loads automatically when you work in that folder. A plain chat elsewhere doesn't read it: there, you paste it in. One folder, one memory, zero repeating yourself.

And it has a sibling: a skill — a small file of instructions (a name, a description of when it applies, a body) that the agent loads when relevant. Teach it once, and the behaviour is automatic every time. If you've built a skill that grills your requests, you already own one. Together they're your two standing-instruction mechanisms: always-on memory beside on-demand behaviour.

Lesson 8 · your activity

Write it once — then catch it remembering

A memory file in your real work folder, pruned sharp, then proven in a session that was never told your preferences.

  1. Pick your real work folder. The folder where your actual work lives — make one now if you don't have one. Not the course folders: this file belongs with your work.
  2. Write CLAUDE.md there, with your guide. Four short sections, your own words: who I am · how I like output · always · never. Say something like Create a file called CLAUDE.md in my work folder — I'll tell you what goes in it.
  3. Prune it, line by line. For each line: would removing this cause a mistake? If not, cut it — and tell your guide about one cut you made. One screen, tops.
  4. The proof. Start a fresh task (+ New task, then Work in a project or folder → your work folder). Ask for something small and real with a deliberately minimal brief — leave out everything the file now covers — e.g. Draft a short note about the schedule change. Then watch: did it honour a preference you never mentioned?
  5. Come back and tell the tale. What did it get right without being told? And in your own words: what's a skill, and how does it differ from this file?

Take these with you

You'll be in a new task, away from this page — your guide will drop a link below to keep these beside you:

  • Your real work folder — never the course folders
  • Four sections: who I am · how I like output · always · never
  • The pruning test, per line: "would removing this cause a mistake?"
  • Proof: + New task → Work in a project or folder → your folder → one minimal real ask
  • It loads when you work in that folder — a plain chat elsewhere needs it pasted
